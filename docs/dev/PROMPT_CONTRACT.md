# プロンプト入出力契約（PROMPT CONTRACT）

**入出力の契約はシステム側で保証されます。** ユーザーが編集するプロンプトファイルは「役割・指示」のみでよく、**現在の状況**と**出力形式**は実行時にコードで自動付与されるため、ユーザーがプレースホルダやJSONキーを意識する必要はありません。

## 1. 仕組み（システム保証）

各エージェントのプロンプトは次の 3 つを連結して組み立てられます。

1. **ユーザープロンプト**（プロンプトファイルの内容）  
   - 役割・指示・トーン・言語など、**自由に編集可能**
2. **現在の状況**（システムがコードで生成して付加）  
   - プロジェクト目標、計画、タスク一覧、作業ディレクトリなど。**ユーザーは触らない**
3. **出力形式**（システムがコードで生成して付加）  
   - 必須のJSON形式やレポート形式。**ユーザーは触らない**

このため、「変数名を忘れた」「出力形式を変えて壊した」といった事態は、**ユーザーが明示的に出力形式を書き換えるようなプロンプトを入れない限り発生しません**。

## 2. カスタマイズの仕方

- **環境変数**: `PROMPT_PLANNER`, `PROMPT_WORKER`, `PROMPT_JUDGE`, `PROMPT_PLAN_JUDGE` で各プロンプトファイルのパスを指定可能。
- **対象プロジェクト内**: 対象プロジェクトの `prompts/` に `planner.md`, `worker.md`, `judge.md`, `plan_judge.md` を置くと、そのファイルが優先して使われます。
- 優先順位: **環境変数 > 対象プロジェクトの prompts/ > デフォルト（orchestragent の prompts/）**。

編集するのは **「役割・指示」の部分だけ** です。ファイル内にプレースホルダ（`{project_goal}` など）を書く必要はなく、書いても無視されます（状況・出力形式は常にシステムが付加するため）。

## 3. システムテンプレート（ファイル）

「現在の状況」と「出力形式」の文言は、Python 内の文字列結合ではなく **テンプレートファイル** で管理しています。配置場所は `prompts/system/` です（ユーザーによる差し替え対象外）。

| エージェント | コンテキスト用 | 出力形式用 |
|-------------|----------------|------------|
| Planner     | `planner_context.md`  | `planner_output.md`  |
| Worker      | `worker_context.md`   | `worker_output.md`   |
| Judge       | `judge_context.md`    | `judge_output.md`    |
| Plan_Judge  | `plan_judge_context.md` | `plan_judge_output.md` |

プレースホルダは `{変数名}`、JSON 内のリテラルな `{` `}` は `{{` `}}` でエスケープします。コードはこれらを読み込み `.format(**kwargs)` で埋めます。

## 4. システムが付与する内容（参考）

ユーザーが契約を守る必要はありませんが、実装の参考として、システムがどのような「現在の状況」と「出力形式」を付加しているかを示します。

### 4.1 Planner

- **付与する状況**: 作業ディレクトリ、プロジェクト目標、現在の計画、前回の Plan_Judge フィードバック、前イテレーションの Judge フィードバック、既存タスク一覧、コードベース概要。
- **付与する出力形式**: JSON（`plan_update`, `new_tasks`, `updated_tasks`, `reasoning` など）。

### 4.2 Worker

- **付与する状況**: 作業ディレクトリ、タスクID・タイトル・説明、関連ファイル。
- **付与する出力形式**: タスク完了レポートの Markdown テンプレート（Intent 含む）。

### 4.3 Judge

- **付与する状況**: プロジェクト目標、現在の計画、タスク数・完了数・失敗数・保留数、完了タスクの結果サマリ、イテレーション番号。
- **付与する出力形式**: JSON（`should_continue`, `reason`, `progress_score`, `drift_detected`, `drift_description`, `recommendations`, `next_iteration_focus`）。

### 4.4 Plan_Judge

- **付与する状況**: 作業ディレクトリ、プロジェクト目標、現在の計画、タスクリストサマリ、コードベース概要、イテレーション番号。
- **付与する出力形式**: JSON（`decision`, `score`, `issues`, `suggested_changes`）。

## 5. 最低限の入力情報（システム全体）

次の 2 つは**システムを動かすための最低限の入力**です。これらは設定（環境変数・config）で渡すもので、プロンプトファイルでは扱いません。

- **PROJECT_GOAL**（環境変数または `agent_config["project_goal"]`）: プロジェクト目標の文字列。
- **作業ディレクトリ**（`project_root` / `working_dir`）: ファイル操作とプロンプト解決の基準。

---

**まとめ**: プロンプトファイルでは「役割・指示」だけを自由に編集してください。現在の状況と出力形式はシステムが必ず付与するため、**ユーザーが契約を気にしなくても、入出力の整合性は保たれます**。
